# Mirk 0.16.0: preparing the public npm release

Date: 2026-11-19. Branch `release/0.16.0-public-prep`, from `main` at `89176f7`. Nothing was
published to any registry. This note is written to be safe in a public repository: it names no
people, machines or unpublished projects.

Marks: **measured** means a command ran and its output was read. **Seen** means read in a file or
on a registry.

## The package set

15 npm packages, all at 0.16.0 (seen in every `package.json`). In dependency order, the order a
publish should follow (measured from the packed `package.json` files; `changeset publish` orders
them itself):

1. `@mirk/sqlite-vec-native` (no Mirk dependencies; optional peer of the store)

## Leak scan

### Method

Each package was built (`pnpm build`) and packed with `pnpm pack`, the same command
`scripts/verify-package-release.mjs` uses, into a temporary folder outside the repository. Every
tarball was unpacked and every file read: `dist` JavaScript and declarations, README, LICENSE,
`package.json`, and the vendored C sources and headers in `@mirk/sqlite-vec-native`. No package
ships source maps or a CHANGELOG.

A script outside the repository reports every line that matches one of these groups:

- names of people and of the studio's agents;
- email addresses, except the npm maintainer address;
- home folders on macOS, Linux and Windows, and paths that start with a tilde;
- machine and network names, private registry names and ports, `localhost` with a port, `.local`
  and `.internal` hosts, tailnet names;
- names of unpublished studio projects, studio coordination files and local-only folders;
- dates, branch names and internal process words;
- keys and tokens (npm, GitHub, AWS, Slack, bearer tokens, private keys, credential literals).

A second case-insensitive pass over the same files checked the project and people names again.

### Positive control

Before trusting the scan, three known strings were planted in a copy of the unpacked
`@mirk/queue`: a home-folder path in `dist/index.js`, an agent's name in `README.md`, and a private
registry URL with its port in `package.json`. The scan reported 3 of 3, and nothing else changed
(measured: the hit list before and after differed by exactly those lines).

Comments in the source reach a tarball through declaration files and source maps. No package ships
a source map: there are no `.map` files, and no `sourceMappingURL` or `sourcesContent` in any file
(measured on the final tarballs). The 879 comment lines in the shipped `.d.ts` files, and the
comments tsup keeps in `dist/*.js`, were read by the scan above and by a second pass for internal
references (tools, reviews, specifications, tickets, repository paths, documents that do not
ship). Neither pass found one. The only paths in `dist` comments are tsup's file markers such as
`// src/internal/connection.ts`, which name the package's own source files. Names of studio
libraries that are meant to be public were also searched for and do not appear.

`pnpm release:verify -- --all --skip-build --skip-test --no-receipt` passed for all 15 packages
after the fixes (measured). It repeats Mirk's own packed-path, private-host and private-path
checks, exports, declarations, and a clean install and import of each tarball.

## README changes

Each package README is its npm page. Changes:

- **`@mirk/store`**: sections reordered by how much a typical user needs them. Vector search is now
  a top-level section beside full-text search, rewritten with a runnable example; before, it sat
  inside the SQLite adapter section after the file-format tables. The log section is shorter and
  its SQL tables moved to a new "File formats" section at the end, with the SQLite and coordination
  formats. Query statistics (new in this release) moved from high in the SQLite section to the end
  of it and lost its benchmark figures; it is automatic and needs no call. The exports table now
  lists `@mirk/store/sqlite-vec` and `@mirk/store/coordination/core`, and marks
  `@mirk/store/coordination` as deprecated, as the code does. "Transactions across memory stores"
  is rewritten in plain words.
- **`@mirk/queue`**: rewritten for a reader who has never seen it. Before, it opened with one
  paragraph of internal terms and an example that used an undefined `db`. Now: what it is and why,
  install, a complete SQLite example and an in-memory one, then items and states, claims,
  `runClaim`, command keys, one active item per key, cancellation and blocked items, managing items,
  history, and storage requirements.
- **`@mirk/artifact`**: the first example now comes before the exports table; headings use one
  style.
- **`@mirk/sqlite-vec-native`**: rewritten. Before, six dense paragraphs with no heading, install
  command or example. Now: what it is, install, use, what happens when it is missing or broken,
  what the tarball holds. One claim was corrected against the code: a binary built for another
  platform falls back to JavaScript search; it does not throw.
- **`@mirk/vector-qdrant`**: added a heading, a "Why" and an install section before the contract;
  the contributor test command moved out.
- **`@mirk/store-libsql`**: the migration section sat after "License"; it and the query statistics
  section now sit at the end of the reference. The contributor section on running tests against a
  libSQL server moved to `CONTRIBUTING.md`. A stale sentence about format 3 was removed.
- The other READMEs (statements, fixtures, migrate, surreal, artifact-opendal,
  artifact-vercel-blob, store-indexeddb, store-postgres, store-markdown) were already written for
  outside readers; only the fixes in the table above changed them.

### Before and after: the opening of the core READMEs

`@mirk/queue`, before:

> Portable durable queue storage over Mirk atomic KV and writer transactions: stored items, atomic
> fenced claims with renewal, keyed single-active admission, and idempotent commands. This package
> opens no connection, runs no workers and holds no policy. […]

After:

> **A durable work queue stored in your Mirk database.** Enqueue items, let one worker at a time
> claim each, and record how it ended, with safe retries and no item run twice by two holders.

`@mirk/store`, before (section order after "How stores behave"): Full-text search, Append-only log,
Graph helpers, The SQLite adapters (Options, `listWhereIn`, Indexes and query plans, Query
statistics, Transactions, …, Shared SQLite file format, Vectors), Atomic mutations, …

After: Vector search, Full-text search, Append-only log, Graph helpers, The SQLite adapters
(Options, Transactions, Awaitable access, Several processes, Backups, Migration policy,
`listWhereIn`, Indexes and query plans, Query statistics), Atomic mutations, Async transactions,
Transactions across memory stores, Async coordination, Encrypted records, Sync by design, File
formats.

`@mirk/artifact`: the opening was already clear and is unchanged.

## Version

The local registry has no 0.16.0 of `@mirk/store` (measured: `npm view @mirk/store@0.16.0` returns
E404 there; its newest is 0.14.0). Public npm has 0.14.0 (measured). So 0.16.0 has not been
published anywhere, and nothing has to be republished: the fixes change only READMEs (and files
that do not ship), so the code in the 0.16.0 tarballs is the code the readiness note verified.

**Recommendation:** publish this branch's content as 0.16.0 to public npm, with no 0.16.1. Merge
the branch into `main`, then follow the Release section of `CONTRIBUTING.md`.

## For the owner

- **The copyright line.** Every tarball's `LICENSE` names a person as the copyright holder, and the
  npm maintainer entry names a personal address. Both are already public on 0.14.0 (seen). Keep
  them, or change the `LICENSE` to an organisation before publishing.
- **`@mirk/sqlite-vec-native` license file.** The package is MIT and ships sqlite-vec's MIT license
  under `dist/native/`, but no license file for Mirk's own code in it.
- **The public repository** holds files that are not in any tarball but are visible to anyone who
  follows the npm page's repository link; they are listed in the private hand-back to the owner,
  not here.
